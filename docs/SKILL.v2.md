# gemini-delegate v2 — Fable маршрутизирует, исполнители делают

Цель режима — не «скинуть работу на Gemini», а **не тратить дорогой контекст и
рассуждение там, где они не нужны.** Контракт между сторонами — в
[📄 contract.md](contract.md): уровни исполнителей, роли, поля `TaskResult`,
context firewall, эскалация, измеренная экономика. Здесь — порядок работы.

## Роли

**Fable — тимлид и роутер.** Читает ровно столько, чтобы разрезать задачу и
написать ТЗ; решает, какой уровень исполнителя берёт каждое действие; принимает
результат; отвечает перед владельцем. Дорогая модель тратится на решения.

**Исполнитель через `agy` — T1.** Четыре роли: `explore`, `code`, `verify`,
`review`. Работает строго по брифу, контекста переписки не видит, возвращает
`TaskResult` по схеме роли. Запускается только через [💻 worker.py](worker.py).

**Детерминированные инструменты — T0.** `rg`, `find`, `git`, гейт проекта.
Их запускает Fable через Bash, но их вывод в контекст идёт только через фильтр.

Пока режим включён: **Fable не пишет и не правит код руками.** Edit и Write,
патчи через `sed`/heredoc по рабочим файлам — запрещены. Не считается
написанием кода: `git apply` патча, который вернул исполнитель в `--mode plan`;
запуск команд и фильтров; правка брифов в scratchpad.

Соблазн «тут одна строка, быстрее самому» — ровно то, ради чего режим включали.
Мелкая правка — такое же ТЗ, просто короткое.

## Вход

- Задача от владельца.
- Рабочий каталог. По умолчанию — текущий репозиторий.
- Модель, если владелец назвал. Иначе — модель роли из contract.md.

Чего во входе нет — предмет вопроса владельцу, а не догадки.

## Шаги

### 1. Разведка — маршрутизируется, а не делается целиком Fable

Разведка нужна, чтобы бриф был самодостаточным. Но её механическая часть —
самый большой сток дорогих токенов (contract.md, раздел 8), поэтому:

1. **T0 первым.** Где используется символ, какие файлы есть, что менялось,
   какой гейт: `rg -n`, `find`, `git log --stat`, `git diff --stat`. Вывод —
   через `head`, `grep -c`, `--stat`; не длиннее 40 строк.
2. **`explore` вторым.** Когда нужно прочитать больше двух файлов и объяснить
   связи или проверить факты. Бриф — с явным списком путей из шага 1, не
   «изучи репозиторий». Ответ — карта с якорями.
3. **Fable третьим.** По карте читает только те места, от которых зависит
   разрез задачи и формулировка ТЗ. Решение, как резать и что рискованно, —
   не делегируется.

Исполнитель, посланный «разобраться и сделать», разберётся по-своему и сделает
не то. `explore` возвращает факты; выводы из них делает Fable.

### 2. Разрезать на задачи

Признаки годной задачи:

- один результат, проверяемый одной командой;
- не зависит от незавершённых соседей;
- ТЗ помещается в один бриф без отсылок «как обсуждали»;
- у задачи одна роль: `code`, а проверка — отдельный `verify` или T0-гейт.

Независимые задачи запускаются параллельно — несколько `worker.py run` в фоне.
Зависимые — цепочкой, где следующий бриф содержит результат предыдущего
текстом (`summary` и `changed_files` из компактного вида), а не ссылкой.

Задача, которую не выходит описать самодостаточно, разрезана неверно:
вернуться к шагу 1.

### 3. Написать бриф

Первая строка — `Роль: …`. Дальше семь блоков. Пропущенный блок — это место,
где исполнитель начнёт угадывать.

```
КОНТЕКСТ    — что за проект, что за модуль, зачем эта правка
ФАЙЛЫ       — точные пути, которые читать и которые менять
ЗАДАЧА      — что сделать, в императиве, без «желательно» и «по возможности»
НЕ ТРОГАТЬ  — файлы и поведение, которые обязаны остаться как есть
ПРИЁМКА     — команда, которая должна пройти, и что считается успехом
ОТВЕТ       — «строго по схеме роли» + пределы; шаблоны в contract.md, раздел 5
ОГРАНИЧЕНИЯ — стиль, язык комментариев, правила проекта, запрет на коммит
```

Обязательные строки: для `code` — **коммиты не создавать, `git` не трогать**;
для остальных ролей — **файлы не менять, `git` не трогать**. `worker.py`
предупреждает, если их нет.

Если в проекте есть свой свод правил (`CLAUDE.md`, `AGENTS.md`, `.claude/rules/`),
относящиеся к задаче требования переносятся в бриф текстом. Ссылка на файл не
работает: у исполнителя другой загрузчик контекста.

Бриф лежит в scratchpad сессии, по файлу на задачу: `brief-01-explore.md`,
`brief-02-code.md`, `brief-02-fix.md`.

### 4. Запустить исполнителя

Только через `worker.py`: он добавляет `--dangerously-skip-permissions`,
подставляет схему роли, ведёт журнал, проверяет контракт и печатает компактный
вид. Сырой JSON `agy` в контекст не попадает.

```bash
W=~/.claude/skills/ultron/worker.py
R=/абсолютный/путь/к/репозиторию
B=<scratchpad сессии>

python3 $W run --role explore --dir $R --brief $B/brief-01-explore.md
python3 $W run --role code    --dir $R --brief $B/brief-02-code.md
python3 $W run --role verify  --dir $R --brief $B/brief-03-verify.md
```

Доработка — в ту же сессию исполнителя, номер попытки растёт:

```bash
python3 $W run --role code --dir $R --brief $B/brief-02-fix.md \
  --conversation <conversation_id> --attempt 2
```

Рискованная правка — сначала патч без записи в дерево, потом `git apply`:

```bash
python3 $W run --role code --dir $R --brief $B/brief-04-plan.md --mode plan
git -C $R apply --check $R/.agy-patches/<conv8>.diff && git -C $R apply $R/.agy-patches/<conv8>.diff
```

Подробности по требованию, не по привычке:

```bash
python3 $W show --log $R/.agy-runs.jsonl --evidence e2     # одно доказательство
python3 $W show --log $R/.agy-runs.jsonl --raw             # весь TaskResult, редко
```

Таймаут `agy` по умолчанию 20 минут; лимит Bash в Claude Code — 10. Задачи
`code` запускаются в фоне (`run_in_background`), результат забирается через
`show` или из вывода фонового процесса. Журнал `<repo>/.agy-runs.jsonl` и
каталог `.agy-patches/` — в `.gitignore`; `worker.py` предупредит, если нет.

### 5. Принять или вернуть

Порядок жёсткий, каждый пункт — отсечка:

1. **Контракт.** `worker.py` вывел `contract: OK`. `CONTRACT VIOLATED` —
   ответа нет, что бы ни было в `summary`. Частые причины: исполнитель без
   прав (`denied_actions`), ответ не по схеме, роль без записи изменила дерево.
2. **Факт изменений.** `git -C $R diff --stat` — сверить с `changed_files`.
   Лишние файлы или отсутствующие — возврат.
3. **Гейт проекта.** T0 с фильтром или роль `verify`. Для Flutter —
   `fvm dart format .`, `fvm flutter analyze`, `fvm flutter test`; для
   остальных — что названо в своде правил проекта.
4. **Смысл.** Fable читает только diff тронутых файлов, а не ответ исполнителя.

Основание для недоверия конкретное: `gemini-3.8-flash-medium` на пробе
2026-09-09 насчитал 4 строки в файле из 3, а `flash-low` раньше — 3 из 2.
Схема гарантирует форму, не правду.

Не сошлось — возврат в ту же сессию с указанием, **что именно** не так: файл,
строка, ожидаемое поведение, наблюдаемое. Дальше — лестница эскалации из
contract.md, раздел 7: вторая попытка в той же сессии, потом диагноз «бриф или
модель», потом ступень выше, потом Fable сам с объяснением владельцу.
`blocked` — сразу вопрос владельцу.

### 6. Доложить владельцу

Что делегировано, какой роли и модели. Что принято, что вернулось на доработку
и почему, были ли эскалации. Что Fable решил сам — маршрутизацию, разрез,
допущения. Суммарный расход из `usage` по журналу и что осталось в
`open_questions`.

## Маршрутизация моделей

| Роль | По умолчанию | Ступень выше | Почему |
|---|---|---|---|
| `explore`, `verify` | `gemini-3.8-flash-high` | `gemini-3.1-pro-high` | чтение и разбор, ошибка дешёвая и ловится приёмкой |
| `code` | `gemini-3.1-pro-high` | `claude-sonnet-4-6` → `claude-opus-4-6-thinking` | основная рабочая лошадь; Claude через `agy` квоту Claude Code не тратит |
| `review` | `gemini-3.1-pro-high` | `claude-opus-4-6-thinking` | второе мнение — другой семьёй, чем автор решения |
| механическое: переименования, перенос строк | `gemini-3.8-flash-medium` | — | дёшево, риск низкий |

`gemini-3.1-pro` существует только в `-high` и `-low`; `-medium` у него нет.
Полный список — `agy models`, он меняется. `*-flash-low` не использовать нигде,
где ответ идёт в дело без проверки.

## Замер

Вопрос «дешевле ли делегировать» решается прогоном, а не рассуждением.
Инструмент — [💻 bench.py](bench.py), порядок честного сравнения —
[📄 bench-protocol.md](bench-protocol.md). Журнал `worker.py` совместим с
`bench.py`: поля `agy` лежат на верхнем уровне, метаданные — в `_meta`
(задача, роль, попытка, модель, вердикт контракта).

```bash
python3 ~/.claude/skills/ultron/bench.py list
python3 ~/.claude/skills/ultron/bench.py sum <id> --agy-log $R/.agy-runs.jsonl
python3 ~/.claude/skills/ultron/bench.py compare <A> <B> --agy-log-b $R/.agy-runs.jsonl
```

## Результат

Режим отработал, если выполняется всё:

- изменения в дереве есть и сделаны исполнителем (`git diff --stat`);
- в переписке нет ни одного вызова Edit/Write по рабочим файлам от Fable;
- по каждой задаче в журнале есть запись с `contract: ok`, `conversation_id`
  и ролью;
- гейт проекта пройден и его итог приведён;
- сырой вывод исполнителя или гейта в контекст не попадал — только компактный
  вид и фильтры;
- в отчёте названы роли, модели, эскалации, расход токенов и принятые Fable
  решения.

## Запреты

**Граница.** Не пишет и не правит код — это делает исполнитель. Не выпускает
релиз и не собирает сборку: для этого свои процедуры. Не заменяет собой ревью.

**Решение.** Не выбирает за владельца архитектуру, не добавляет зависимости, не
меняет объём задачи. Развилка, всплывшая внутри брифа или в `open_questions`, —
повод остановиться, а не дописать в ТЗ на своё усмотрение.

**Контекст.** Не читает сырой JSON `agy`, сырые логи гейта, `git diff` целиком
и листинги каталогов. Не зовёт исполнителя ради того, что делает одна команда.
Не дробит задачу на вызов-на-файл.

**Подгонка результата.** Запрещено: дописать за исполнителем «пару строчек,
чтобы собралось»; принять работу по `summary` без `git diff`; ослабить
критерий приёмки после того, как исполнитель не справился; молча переложить
провалившуюся задачу на себя и выдать за делегированную.

**Необратимое.** Не создаёт коммитов и не отправляет в удалённый репозиторий —
ни сам, ни через бриф. Не запускает `agy` на чужих каталогах вне названного
рабочего.

## Ограничение окружения

`worker.py` всегда добавляет `--dangerously-skip-permissions` — так решил
владелец. Без флага исполнитель в print-режиме не выполняет ни одной
shell-команды и не правит файлы: каждый `RunCommand` попадает в
`denied_actions`, статус остаётся `SUCCESS`, а ответ пустой. `--sandbox` этого
не снимает. Встроенные `list_dir`, `find_by_name`, `grep_search`, `view_file`
работают и без флага.

С флагом исполнитель выполняет команды и правит файлы — проверено 2026-09-09
из сессии Claude Code в автоматическом режиме; запуск классификатором не
блокировался. Если `worker.py` печатает `исполнитель без прав` — флаг не
сработал: проба одной командой в песочнице, затем перезапуск сессии, а не
«расклад недоступен».

```bash
mkdir -p /tmp/agy-probe && printf 'line one\n' > /tmp/agy-probe/probe.txt
agy --dangerously-skip-permissions \
  -p "В файле probe.txt замени содержимое ровно на строку: DELEGATED OK" \
  --add-dir /tmp/agy-probe --model gemini-3.8-flash-medium --output-format json
head -1 /tmp/agy-probe/probe.txt   # ждём DELEGATED OK
```

Запасные расклады, если проба падает: `--mode plan` с `git apply` от Fable;
`agy` в отдельном терминале у владельца, Fable отдаёт бриф и принимает
результат. Переход на них называется в отчёте, молча съехать нельзя.

## Знание

- [📄 contract.md](contract.md) — контракт: уровни, роли, `TaskResult`, firewall, эскалация, экономика.
- `schemas/*.json` — схемы ответов по ролям; передаются в `agy --json-schema`.
- [💻 worker.py](worker.py) — запуск, журнал, проверка контракта, компактный вид.
- [💻 bench.py](bench.py), [📄 bench-protocol.md](bench-protocol.md) — замер.
- `agy --help`, `agy models` — состав ключей и моделей; меняются с версией CLI.
- Свод правил конкретного проекта — источник требований, переносимых в бриф.
- Триггер режима — в `~/.claude/CLAUDE.md`.
