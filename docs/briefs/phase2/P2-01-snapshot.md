КОНТЕКСТ — Проект ultron, рабочий каталог = корень репозитория: утилита, в которой Claude пишет TaskSpec, исполнитель через Antigravity CLI (agy) делает работу, обратно возвращается TaskResult. Python 3.10, только стандартная библиотека. Ядро фазы 1 собрано, тесты фазы 1 зелёные. Фаза 2 — транзакционное дерево: снимки рабочего состояния в объекты git, восстановление чужих файлов из baseline самим runtime, гейт независимо от доклада, чистая эскалация. Карта — docs/internals.md, раздел «Фаза 2: транзакционное дерево»; тесты в tests/ — арбитр: если карта и тест расходятся, прав тест. Уже готовы и менять их нельзя: ultron/policy.py, ultron/schemas/, tests/, docs/. Гейт запускается из корня рабочего каталога. Принцип фазы: runtime никогда не делает git checkout, git reset или git stash по пользовательскому дереву — только снимки во временный индекс и восстановление файлов из блобов.
ФАЙЛЫ — читать: docs/internals.md (раздел «ultron/snapshot.py»), tests/test_snapshot.py, tests/helpers.py, ultron/policy.py. Создать: ultron/snapshot.py.
ЗАДАЧА — Реализуй модуль ultron/snapshot.py по разделу карты: frozen-датакласс Snapshot(label, commit, tree, files, modes) и функции take_snapshot, diff_paths, restore_paths, restore_all, patch_between, list_snapshots, drop_snapshots. Снимок берётся через временный индекс (GIT_INDEX_FILE), git add -A ., git write-tree, git commit-tree с авторством ultron из переменных окружения (GIT_AUTHOR_NAME/EMAIL и GIT_COMMITTER_NAME/EMAIL), git update-ref refs/ultron/<task>/<label>; настоящий индекс и рабочее дерево не меняются. Байткод (__pycache__/ в пути, .pyc) отбрасывается только в diff_paths. Восстановление пишет байты блоба через git cat-file blob и выставляет бит исполняемости по режиму 100755; путь, которого нет в снимке, удаляется. Прогони гейт сам перед ответом: python3 -m unittest tests.test_snapshot -v
